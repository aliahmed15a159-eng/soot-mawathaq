# 𓂀 صوت — منصة انتخابات إلكترونية بالتحقق من الهوية

> منصة تصويت لا تُحسب فيها إلا **هوية واحدة حقيقية**: الناخب يسجّل بياناته، يصوّر بطاقته، ويأخذ سيلفي حيّ من الكاميرا — والنظام يقارن ويقرّر، وبعدها فقط يُصدر **رمز اقتراع سرّي** يُستخدم مرة واحدة.

مبنية بـ **Node.js** بدون أي مكتبات خارجية على الخادم، و**قاعدة بيانات Supabase (PostgreSQL)** — وتشتغل فورًا في **وضع تجربة محلي** لو مفاتيح Supabase غير مضبوطة.

## ٢) ربط Supabase (قاعدة البيانات الحقيقية)

**الخطوة ١ — إنشاء المشروع:** من [supabase.com](https://supabase.com) → New project (اختار منطقة قريبة مثل `eu-central-1`).

**الخطوة ٢ — إنشاء الجداول:** افتح `SQL Editor` → `New query` → الصق محتوى الملف **`supabase/schema.sql`** كاملًا → Run.
الملف ينشئ: `voters` · `elections` · `candidates` · `vote_tokens` · `ballots` · `reviews` · `audit_log` + العرض `election_results`، ويضبط سياسات RLS (لا وصول للجمهور، والخادم يمرّ بمفتاح `service_role`).

**الخطوة ٣ — المفاتيح:** من `Settings → API` انسخ `Project URL` و`service_role key`:

```bash
cp .env.example .env
# ثم املأ:
# SUPABASE_URL=https://xxxxx.supabase.co
# SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
# SESSION_SECRET=<سلسلة عشوائية طويلة>
# IDENTITY_SALT=<سلسلة عشوائية أخرى>
```

**الخطوة ٤ — التأكد من الاتصال:**

```bash
node server.js
# [db] متصل بـ Supabase          ← الوضع الحقيقي
# أو
# [db] وضع التجربة — قاعدة بيانات محلية   ← المفاتيح غير مضبوطة
curl localhost:3000/healthz        # {"ok":true,"mode":"supabase"}
```

بعد الربط، كل شيء يعمل كما هو: التسجيل يكتب في `voters`، التحقق يصدر رمزًا في `vote_tokens`، والتصويت يكتب في `ballots` — **وبدون أي تغيير في الكود**.

> ⚠️ مفتاح `service_role` سيرفر فقط. لا يوضع أبدًا في كود المتصفح ولا في مستودع عام.

## ٣) آلية العمل (رحلة الناخب)

```
① التسجيل            البيانات الأساسية + الرقم القومي + OTP
     ▼
② تصوير البطاقة       قراءة آلية (OCR) + فحص جودة الصورة
     ▼
③ سيلفي حيّ           تحدي حركة عشوائي (لف الرأس / رمش / اقتراب) ← يمنع الصور والفيديوهات
     ▼
④ مطابقة الوجه ١:١     نسبة تشابه + «حد الفصل» ← قبول / مراجعة بشرية / رفض
     ▼
⑤ إصدار رمز اقتراع    رمز عشوائي يُخزَّن مُجزَّأً (Hash) في جلسة موقّعة HttpOnly — لا يظهر للمتصفح
     ▼
⑥ الاقتراع            اختيار + تأكيد نهائي → الرمز يُحرَق (used_at) ذريًّا
     ▼
⑦ الإيصال            رقم مرجعي يثبت الاحتساب بدون كشف الاختيار
```

### الأمان الجوهري: فصل مسار الهوية عن مسار الصوت

| مسار التحقق (`voters` + `vote_tokens`) | مسار الاقتراع (`ballots`) |
|---|---|
| يعرف: مين تحقق، ومين استلم رمزًا | يعرف: الاختيار فقط |
| يحفظ بصمة الرقم القومي (SHA-256 + ملح) — لا الرقم نفسه | **لا يوجد به أي عمود للناخب** |
| الرمز مُجزَّأ، ويُحرق بعد أول استخدام | علاقة الصوت بالهوية = غير موجودة بالتصميم |

**النتيجة:** صوت واحد لكل إنسان (فريد على مستوى الهوية) + سرية كاملة (حتى مسؤول النظام لا يستطيع ربط صوت بصاحبه).

### طبقات تمنع التحايل على الكاميرا
- **تحدي حركة عشوائي** + قياس توقيت الاستجابة الطبيعية (استجابة فورية جدًا أو بطيئة جدًا ⇒ رفض).
- **كشف إعادة الاستخدام:** لو نفس الصورة بالحرف في البطاقة والسيلفي ⇒ رفض فوري.
- **قياس الجودة** (إضاءة/تباين/حدّة): صور رديئة ⇒ رفض قبل المطابقة أصلًا.
- **منطقة رمادية:** أي حالة بين عتبتين ⇒ إحالة إلى **لجنة بشرية** تراجع الصورتين (الصور تُحذف بعد القرار).
- **حدود معدل الطلبات** لكل IP، وحد أصوات لكل جهاز في منصة الاقتراع المشتركة.

### سجل التدقيق
كل قرار حساس (`register_created`, `verification_approved`, `review_approved`, `ballot_cast`, …) يُسجَّل في `audit_log` بمَن ومتى وماذا — بدون كشف هوية الناخب في عمليات التصويت.

## ١٢) المرحلة الثانية — التحقق الحقيقي وكشوف الناخبين

منصة «صوت» بتشتغل افتراضيًا بمحرك تحقق **تجريبي** (بدون أي مفاتيح خارجية) عشان تقدر تعرضها وتجرّبها فورًا.
لما تحط مفاتيح حقيقية في `.env`، المزوّد بيتفعّل تلقائيًا **من غير أي تغيير في الكود**.

### أ) الاختيار بالمفتاح

| المزوّد | المتغيرات | ملاحظة |
|---|---|---|
| مطابقة الوجه | `VERIFY_PROVIDER=demo\|facepp\|rekognition\|azure` + مفاتيحه | demo افتراضيًا |
| قراءة البطاقة (OCR) | `OCRSPACE_KEY` \| `GOOGLE_VISION_KEY` \| `AZURE_VISION_KEY`+`ENDPOINT` (اختيار تلقائي) | `OCR_PROVIDER` لتثبيت مزوّد بعينه |
| كود الموبايل | `OTP_MODE=off\|console\|sms` + مفاتيح Twilio/Vonage/SMS Misr | console = عرض على الشاشة للتجربة |
| كشوف الناخبين | `REGISTER_MODE=strict` + جدول `voter_roll` | انظر `supabase/migrations/002_phase2.sql` |

### ب) الترقية (مرة واحدة)

- **الأسهل:** Supabase Dashboard → SQL Editor → الصق `supabase/migrations/002_phase2.sql` → Run (آمن للتكرار).
- **بديل آلي:** ضع `DATABASE_URL` (رابط Pooler، منفذ 6543) في `.env` ثم:
  `node tools/pg-apply.js --all`  ← السكيما + كل الترقيات بالترتيب.

### ج) الصفحات والتبويبات الجديدة

- `/otp` — خطوة كود الموبايل بعد التسجيل (تُخطّى تلقائيًا لو `OTP_MODE=off`).
- لوحة الإدارة → تبويب **كشوف الناخبين**: استيراد CSV/لصق، وعدّاد أفراد الكشف.
- لوحة الإدارة → تبويب **المزوّدون**: المزوّد النشط لكل طبقة + المفاتيح الناقصة.

### د) تفاصيل تقنية

- المطابقة العربية: تطبيع كامل + `tokenScore` (الاسم الموصول/المفصول مثل «عبدالرحمن» ↔ «عبد الرحمن» ≈ 0.95).
- قرار البطاقة: قبول ≥ 0.62 · فشل قاطع لو الرقم القومي < 0.6 أو الاسم < 0.45.
- كشف الحياة: حركات (رمشة/يمين/شمال/قرّب/ابتسامة) + بوابات لكل حركة + قراءة المزوّد لو متاح.
- OTP: صلاحية 5 دقايق · إعادة إرسال 60 ثانية · 5 محاولات · الكود مُجزَّأ HMAC-SHA256 · الحالة في الجلسة الموقّعة (بدون أي عمود جديد).
- تدقيق نداءات المزوّدين: جدول `provider_calls` + تسجيل زمن الاستجابة.
